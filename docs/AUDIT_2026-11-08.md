## Исправления

| Проблема | Изменение | Результат |
| --- | --- | --- |
| Все главы и диалог справки загружались даже на экране входа | `PageHelpDialog` вынесен в динамический импорт; главы загружаются при открытии справки или руководства | Меньше стартового JavaScript |
| Каталоги запрашивали страницы строго последовательно | `allPages` загружает до четырёх следующих страниц одновременно | Меньше последовательных сетевых ожиданий; порядок строк сохранён; ошибка любой страницы отклоняет весь каталог |
| Обычные и аналитические Excel-экспорты собирали XML/ZIP внутри event loop | Все ветки генерации используют `asyncio.to_thread` | Сборка файла больше не занимает поток обработки async-запросов; доступ к AsyncSession остаётся в его потоке |
| Общий заголовок справки мог перезаписывать заголовок главы при первом открытии | Метаданные глав принадлежат `HelpPage`, остальных рабочих страниц — `RouteMetadata` | Согласованные title, description, Open Graph и Twitter |
| Метаданные определялись по неполному совпадению URL | Используются те же правила сопоставления маршрутов, что и в React Router | `/warehouse-extra` и `/warehouse/missing` получают метаданные отсутствующей страницы |
| Вкладки выпуска и склада продукции имели заголовок планирования | Учитывается `tab=release` и `tab=stock` | Точные названия вкладок в браузере |
| Неизвестная глава показывала начало инструкции | Добавлен экран «Глава не найдена» со ссылкой на начало | Адрес и содержимое больше не противоречат друг другу |
| nginx возвращал HTML приложения со статусом 200 вместо отсутствующего robots.txt, sitemap.xml, изображения или JS | Добавлен отдельный обработчик статических расширений с `try_files ... =404` | Корректный 404 для отсутствующей статики; существующие файлы без хеша кешируются на час |

API и media используют `^~`, поэтому правило статических расширений не перехватывает
запросы к backend. Ресурсы Vite с хешами сохраняют годовой кеш, HTML и service worker —
обязательную перепроверку. Общие `add_header` остаются на уровне server:
в nginx собственный `add_header` внутри location изменил бы их наследование.
См. [документацию nginx](https://nginx.org/en/docs/http/ngx_http_headers_module.html).

## Измерение стартовой сборки

Две локальные production-сборки в одном окружении. Суммируются уникальные JS/CSS из
`script`, `modulepreload` и `stylesheet` в `dist/index.html`. Gzip рассчитан локально
для тех же файлов; это не измерение переданных байтов на production-сервере.

| Показатель | До | После | Изменение |
| --- | ---: | ---: | ---: |
| JavaScript | 494 823 байт | 453 730 байт | −8,3% |
| CSS | 156 474 байт | 154 061 байт | −1,5% |
| JS + CSS после gzip | 181 197 байт | 170 709 байт | −5,8% |
| Количество стартовых JS/CSS-файлов | 12 | 15 | +3 |

Разбиение общих модулей добавило три стартовых запроса. Оценка времени загрузки требует
повторного Lighthouse на опубликованной версии, особенно при HTTP/1.1. Текущая конфигурация
nginx включает HTTP/2. Числа выше подтверждают уменьшение объёма, а не новый балл Lighthouse
или измеренное улучшение Core Web Vitals.

Воспроизводимая проверка:

```powershell
cd frontend
npm run build
npm run bundle:report
```

Для каталога из девяти страниц теперь нужны три последовательных этапа запросов
(первая страница и две группы по четыре), вместо девяти. Фактический выигрыш зависит
от сети и времени выполнения запросов на сервере. Лимит не позволяет отправить все
страницы большого каталога одновременно.

## SEO и индексация

README определяет продукт как приватную производственную систему. Сохранены `noindex`
в исходном HTML, динамических метаданных и HTTP-заголовках. Sitemap рабочих URL,
публичные canonical и разметка рекламного продукта не добавлялись. Начальный Open Graph
title согласован с HTML title и Twitter.

`robots.txt` разрешает обход, чтобы поисковик мог прочитать `noindex`; блокировка обхода
через `Disallow: /` помешала бы этому. Это соответствует
[рекомендации Google Search Central](https://developers.google.com/search/docs/crawling-indexing/block-indexing).
Для поискового продвижения нужен самостоятельный публичный раздел с разрешённым
к публикации содержимым. Авторизация остаётся механизмом ограничения доступа к данным.
